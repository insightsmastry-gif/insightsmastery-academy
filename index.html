Why this exists

Notes worth keeping, published the moment they change

Every handbook started as a working file. Instead of letting it rot in a folder, the repository turns it into a readable page and a printable PDF — automatically.

Auto-published notes

Drop an HTML handbook into notes/. The build reads its headings, word count and reading time, then lists it everywhere — no template edits, no config.

Printable PDF handbooks

Each note ships with a print-ready companion. Take it into a workshop, mark it up, hand it to a client — the layout is designed for paper, not for a scroll bar.

Reader mode with a live TOC

Notes open in a distraction-free reader: sticky table of contents, active-section highlighting and a progress bar so a 20-minute reference never feels endless.

Search and filters that keep up

Type to filter the library by title, topic or tag — results update as you type, entirely in the browser. Press / anywhere to jump into the search box.

Dark mode that respects you

The theme follows your system by default, remembers your choice after that, and paints before first render — so there is no white flash at 11pm. Toggle it with T.

Zero tracking, static hosting

No analytics, no cookies, no third-party scripts, no backend. Plain files on GitHub Pages — which is also why the pages load before you finish blinking.

How it works

Three steps from a working file to a published handbook

1

Add the file

Save the handbook as HTML in notes/, or the printable version as a PDF in pdfs/. Naming is the only convention — matching stems link a note to its download.

2

Push to GitHub

A commit triggers the workflow. It scans both folders, extracts titles, headings, tags and sizes, and writes a fresh content/manifest.json.

3

The site rebuilds itself

GitHub Pages redeploys and the new handbook appears in the library, in search, in the counters above and in the downloads page. No code changes required.
